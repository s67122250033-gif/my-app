1. ปัญหาและวัตถุประสงค์ (Problem & Objective)
ที่มาความสำคัญและสิ่งที่ระบบเข้ามาแก้ไข
  • ปัญหาเดิม: การแจ้งซ่อมด้วยกระดาษล่าช้า ข้อมูลใบแจ้งซ่อมสูญหาย ขาดระบบติดตามสถานะแบบ Real-time และขาดการเก็บประวัติอย่างเป็นระบบ
  • วัตถุประสงค์หลัก:
    • พัฒนา Web Application เชื่อมต่อ Firebase Realtime Database ให้ผู้ใช้งานแจ้งซ่อมและติดตามสถานะได้ทันที
    • ช่วยให้ช่างเทคนิคจัดลำดับความสำคัญ และอัปเดตขั้นตอนการซ่อมได้อย่างมีประสิทธิภาพ
    • ช่วยลดภาระงานเอกสารและลดการตอบคำถามผู้ใช้งานเกี่ยวกับสถานะงานซ่อม

7. โครงสร้างข้อมูล (Data Architecture)
การออกแบบโครงสร้างฐานข้อมูล Firebase Realtime Database (Flat Structure)
  • Database Model: Denormalized Style เชื่อมโยงด้วย Foreign Key Identification
  • Nodes หลักในระบบ:
    • equipment: เก็บข้อมูลอุปกรณ์ (EQ001, EQ002...) พร้อมสถานะ เช่น Ready, Under Repair
    • users: เก็บข้อมูลผู้ใช้งาน และจำแนกสิทธิ์การใช้งาน (Admin, Technician, User)
    • repair_tickets: เก็บข้อมูลใบแจ้งซ่อม (TK001...) ผูกกับ `equipment_id` และ `user_id`
